# 人工真机验证清单（Manual Test）

> 适用对象：最终用户在真实 Windows + WebView2 环境下复核。验收环境无法自动化 GUI 交互，
> 以下 M-1 ~ M-10 覆盖 checklist 中标注「需人工真机验证」的项，每步含预期结果。
> 前置：启动 `app/build/bin/app.exe`（或 `wails build` 最新产物）。

## M-1 启动与窗口（A-5 / I-7）
1. 双击 `app/build/bin/app.exe`。
   - 预期：10s 内出现窗口（标题「SuperMDP · Markdown 预览器」），无控制台窗口、无报错弹窗、不崩溃。
2. 拖动窗口边角缩到最小（800×600）。
   - 预期：布局不破损、无横向滚动条、工具栏/状态栏/空状态完整可见。
3. 依次拉宽到 900 / 1280 / 1600。
   - 预期：目录栏宽度自适应（≤1024px 时 220px），正文区 max-width 760px 居中，无溢出错位。

## M-2 打开文件对话框（F-1）
1. 点击工具栏「打开」按钮（或 Ctrl+O）。
   - 预期：弹出原生 Windows 文件对话框，标题「打开 Markdown 文件」；文件类型过滤只显示
     `*.md;*.markdown;*.txt;*.mdown`。
2. 直接点「取消」。
   - 预期：对话框关闭，界面无变化、状态栏无报错。

## M-3 拖拽打开（F-2 / 空状态-拖拽）
1. 从资源管理器拖一个 `.md` 文件到窗口。
   - 预期：拖入时出现半透明遮罩 + 白色虚线框 + 「释放以打开文件」；释放后文件打开、遮罩消失。
2. 拖一个 `.txt` / `.exe` 文件到窗口。
   - 预期：`.txt` 可打开（过滤器含 txt）；`.exe` 等显示状态栏 danger 提示「不支持的文件类型」，4s 后消失。
3. 拖入后按 Esc 或拖出窗口。
   - 预期：遮罩消失，不打开文件。

## M-4 自动刷新与删除提示（F-3 / F-4 / F-5）
1. 打开 `docs/acceptance/fixtures/sample.md`。
2. 用任意编辑器修改该文件并保存（内容变更，如加一行标题）。
   - 预期：约 300ms 后预览自动刷新，状态栏文件名/大小/字数/渲染耗时更新，无闪烁无卡死。
3. 快速连续保存 3 次。
   - 预期：只产生一次或少量刷新，不出现渲染风暴/白屏。
4. 在资源管理器中删除（或重命名）该文件。
   - 预期：状态栏出现 danger 色提示「文件已被删除」（或「文件已被移动或重命名」），预览保留，不反复报错。
5. 点工具栏「刷新」按钮（或 Ctrl+R / F5）。
   - 预期：重新读取文件（删除场景下显示错误提示），无崩溃。

## M-5 视觉核验（B / D / I-2 / I-4 / spec §8）
打开 `docs/acceptance/fixtures/sample.md`，light 与 dark 主题各过一遍：
- 标题 h1–h6 字号阶梯清晰，h1/h2 底部有细分隔线；正文 15px、行高舒适、中英文混排无错位。
- 粗体/斜体/删除线/行内代码样式正确；删除线文字为 muted 灰（修复 P2-2 前为默认黑，属已知偏差）。
- 表格 1px 细边框、表头加粗、对齐符合 markdown 写法（左/中/右）。
- 引用块：左 3px 竖线 + 淡底 + muted 文字；嵌套引用正常。
- 任务列表：自绘方形复选框，勾选为 accent 蓝 + 白勾；点击无反应（只读 disabled，**不改变勾选状态**）。
- 代码块：头部语言标签（小写）+ 「复制」按钮；hljs 配色与主题和谐（非官方主题色）。
- 图片（如有）：居中、max-width 100%、1px 边框。
- 脚注 `[^1]` 上标链接可跳转至文末脚注区。

## M-6 代码高亮抽查（C-1 / C-2）
打开 `sample.md` §4，检查 js/go/rust/python/bash/sql/diff 代码块关键词着色；再自建含
`dockerfile`/`powershell` 标注的代码块查看降级行为（修复 P2-3 前为纯文本，属已知偏差）。
- 预期：36 种内置语言着色正确；无语言标注块以「text」标签显示、内容不转义错乱。
- 另：复制按钮点击后变「已复制」约 1.6s 还原；粘贴到记事本内容与代码块一致。

## M-7 复制按钮（C-3）
打开 `sample.md`，对 js 代码块点「复制」→ 粘贴到记事本。
- 预期：按钮文字变「已复制」，粘贴内容为源码（不含语言标签/行号）。

## M-8 KaTeX / mermaid 开关与渲染（D / E）
1. 打开 `sample.md` §5、§6：行内/块级公式正常；flowchart/sequenceDiagram/gantt 三图渲染、
   居中、不超出内容区；长公式容器内横向滚动不撑破版面。
2. 打开设置弹层（工具栏齿轮）：关闭「数学公式 (KaTeX)」→ 公式变回 `$...$` 原文；
   关闭「图表 (mermaid)」→ 图表变回代码块；再开启恢复。开关即时生效、无需重载文件。
3. 切换主题（Ctrl+T 或工具栏按钮）：mermaid 图应随主题重新渲染换肤（已实现，若有未换肤情况请记录）。
4. 重新启动应用：设置开关状态应保持（localStorage `supermdp:settings`）。

## M-9 目录（TOC）交互（I-5 / spec §8-G）
打开 `sample.md`（含 ≥8 个标题）：
- 目录项按层级缩进；点击目录项平滑滚动到对应标题（标题顶部不被工具栏遮挡）。
- 向下滚动阅读区：当前视口内标题对应的目录项高亮（accent 左边条）并保持可见（scrollspy）。
- 工具栏目录开关（Ctrl+1）：折叠/展开平滑过渡，阅读区随之扩展，无跳动。

## M-10 性能与 5MB 大文件（G-1 / G-2，验证 P1-1 修复效果）
1. 打开 `docs/acceptance/fixtures/big-5mb.md`（5.0MB，混合段落/代码/表格/公式）。
   - 预期（修复后目标）：打开到可交互 < 2s；渲染期间工具栏仍可点击；状态栏显示渲染耗时。
   - 当前已知问题：约 3.5–6s 冻结（P1-1）。若 T5 已修复，记录实际耗时作为回归数据。
2. 打开后滚动到底再回顶。
   - 预期：滚动流畅、无持续卡顿。
3. 连续快速 Ctrl+R 三次。
   - 预期：最终内容正确，无白屏、无渲染风暴。

## M-11 编码与边界文件（F-6 / F-7 / H）
1. 依次打开 `docs/acceptance/fixtures/gbk-sample.md`（GBK）、`utf16le-sample.md`（UTF-16LE+BOM）、
   `bom-only.md`（仅 BOM）、空文件（新建 0 字节 .md）。
   - 预期：GBK/UTF-16LE 中文正常不乱码；bom-only 与空文件显示空状态（不报错）；状态栏显示编码徽标（GBK / UTF-16LE）。
2. 打开 `docs/acceptance/fixtures/edge.md`（XSS 变体 + 损坏语法）。
   - 预期：**无任何脚本执行/弹窗**；svg/onload、img onerror、details ontoggle、data:/javascript: 链接
     均以清洗后文本显示；损坏围栏代码块、非法公式、mermaid 语法错误优雅降级（状态栏提示），不白屏不崩溃。
3. 打开 `sample.md` §8 安全用例区。
   - 预期：`<script>`、`<img onerror>`、`javascript:` 链接、`<iframe>` 均不执行（可开 DevTools 确认 DOM 无 on* 属性）。

## M-12 快捷键与只读性（§7.5 / K）
1. Ctrl+O / Ctrl+R / Ctrl+T / Ctrl+1 / Esc（关弹层、关拖拽遮罩）逐一验证。
   - 预期：动作正确；Esc 关闭弹层与遮罩。
2. 全文检查：无任何可输入/可编辑区域（无光标输入框、无 contenteditable）；无保存/导出/「复制为 HTML」入口。
   - 预期：界面仅「打开/刷新/目录/主题/设置/复制」按钮；正文可选中复制（只读预览正常能力）。
